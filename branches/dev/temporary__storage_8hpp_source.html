48/**
49 * @brief Per-thread linear allocator for short-lived, frame-scoped allocations.
50 * Same idea as Jai's `Temporary_Storage`.
51 * @details Wraps a `std::pmr::monotonic_buffer_resource` in thread-local
52 * storage. Every thread gets its own instance lazily on first use (Meyer's
53 * singleton). The hot allocation path is a plain bump pointer with no atomics:
54 * thread-local storage is the only synchronization mechanism, and it's
55 * sufficient because no other thread ever touches this instance.
56 *
57 * Self-registers into a global, lock-free, singly-linked registry on
58 * construction so `ResetAllTemporaryStorage()` can reach every thread's
59 * instance. Registration is a CAS push onto the registry head, of a small
60 * heap-allocated, deliberately-leaked `RegistryNode`(NOT of the
61 * `TemporaryStorage` object itself). This distinction matters: `this` is
62 * `thread_local`, and its storage is reclaimed by the runtime as soon as
63 * the owning thread exits (and may be reused for another thread's block
64 * afterwards). A registry built by linking `this` directly would leave
65 * `ResetAll()` walking into freed/reused memory the moment any registered
66 * thread exits. The `RegistryNode` instead lives on the heap and is never
67 * freed, so it's always safe to read; it holds a raw pointer back to the
68 * (possibly already-destroyed) `TemporaryStorage` plus an atomic flag that the
69 * destructor sets before the object goes away, and which `ResetAll()` must
70 * check before dereferencing that pointer. There is deliberately no unlinking
71 * of nodes from the list, so `ResetAll()` can walk it concurrently with new
72 * threads registering without any locking or hazard-pointer/epoch reclamation
73 * machinery. This is the right trade-off for a long-lived, roughly-fixed-size
74 * worker thread pool, but a poor fit for workloads that spawn large numbers of
75 * short-lived threads over the life of the process, since each one permanently
76 * grows the registry.
77 *
78 * @warning `Reset()` invalidates every pointer and object previously handed out
79 * by this thread's resource. Only call it at a point where nothing on this
80 * thread still holds a temporary allocation (e.g. end of frame, end of task).
81 */
82class TemporaryStorage final : public std::pmr::memory_resource {
83public:

119 /**
120 * @brief Rewinds every registered, still-live thread's resource.
121 * @details Performs a traversal of the registry's linked list, starting
122 * from the current head and following each node's immutable `next`
123 * pointer, so the traversal itself cannot race with a node being freed.
124 *
125 * This function makes no attempt to synchronize with threads that might
126 * be concurrently allocating from (as opposed to merely registering or
127 * exiting) the resources it resets, the caller is responsible for
128 * guaranteeing that no other thread is allocating from temporary
129 * storage while this runs (e.g. only call it from a single coordinating
130 * thread at a full frame barrier, after every worker has quiesced). New
131 * threads may safely register, and existing threads may safely exit,
132 * concurrently with this call; those races are handled.
133 * @warning Invalidates all outstanding allocations on every registered
134 * thread whose node this call successfully claims.
135 */
136 static void ResetAll() noexcept {
137 HELIOS_MEMORY_PROFILE_SCOPE_N("helios::mem::TemporaryStorage::ResetAll");
138 ResetAllImpl();
139 }
140
141 /**
142 * @brief The memory resource backing this thread's temporary allocations.
143 * @return A reference to the thread-local memory resource

149private:
150 /**
151 * @brief A registry entry, heap-allocated and intentionally never freed.
152 * @details Kept separate from `TemporaryStorage` itself precisely because
153 * `TemporaryStorage` is `thread_local` and does not outlive its thread,
154 * whereas the registry (and anything `ResetAll()` might concurrently be
155 * reading) must be safe to touch for the life of the process. See the
156 * class-level note for the full rationale.
157 *
158 * `Reset()` mutates `monotonic_buffer_resource`'s internal chunk list and is
159 * not thread-safe against a second concurrent call, and the owning thread's
160 * teardown of `upstream_resource_` in `~TemporaryStorage()` is effectively
161 * a second, concurrent call to the same non-thread-safe machinery if
162 * `ResetAll()` races it.
163 */
164 enum class NodeState : uint8_t { kActive, kBusy, kRetired };
165
166 struct RegistryNode {
167 // Immutable after construction, set before this node is published via
168 // the CAS in TemporaryStorage's constructor. Forms the intrusive
169 // singly-linked list; never mutated again, so ResetAll() can traverse
170 // it without synchronizing on anything but the head.
171 RegistryNode* next = nullptr;
172
173 // The thread-local instance this node describes. Only ever
174 // dereferenced while `state` is held at kBusy by the dereferencing
175 // side (see NodeState doc comment above); never dereferenced from the
176 // node's own owner past that owner's destructor.
177 TemporaryStorage* owner = nullptr;
178
179 // kActive: owner is live and not currently being reset by anyone.
180 // kBusy: exclusively claimed, either by ResetAll() calling Reset(), or
181 // by the owning thread's destructor tearing upstream_resource_ down.
182 // Whoever holds kBusy has sole rights to touch upstream_resource_.
183 // kRetired: owner is destroyed; must never be dereferenced again.
184 std::atomic<NodeState> state{NodeState::kActive};
185 };
186

191 * `registry_head_`: read the current head into the new node's `next`,
192 * then CAS the head from that value to the new node, retrying with the
193 * updated head on failure. A node's `next` is never modified again after
194 * a successful CAS, which is precisely what lets `ResetAll()` traverse
195 * the list without synchronizing with concurrent pushes beyond a single
196 * acquire load of the head.
197 */
198 TemporaryStorage() {
199 HELIOS_MEMORY_PROFILE_SCOPE_N("helios::mem::TemporaryStorage::Init");
200 Init();
201 }
